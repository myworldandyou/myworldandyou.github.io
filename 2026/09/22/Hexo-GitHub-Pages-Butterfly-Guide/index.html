Hexo + GitHub Pages + Butterfly 博客搭建与部署教程

本文记录本站使用的博客部署方案：用 Hexo 管理文章和生成静态页面，以 Butterfly 作为主题，通过 GitHub Pages 对外发布。完成配置后，日常更新只需要编写 Markdown、预览、保存源码和部署网页。

部署结构

本站在同一个 GitHub 仓库中使用两个分支：

分支 保存内容 用途
hexo-source Markdown、Hexo 配置、主题和依赖清单 保存可继续编辑的博客源码
main HTML、CSS、JavaScript 和图片 由 GitHub Pages 直接发布

Hexo 目录说明

路径 作用
_config.yml 站点、链接、生成规则和部署设置
source/_posts Markdown 文章源文件
themes 主题目录
scaffolds 新文章和页面的模板
public Hexo 生成的静态网站
package.json 项目命令和依赖清单
node_modules 本机安装的依赖，不应手工编辑

根目录和主题目录都可能存在 _config.yml。根目录配置整个站点，主题配置文件控制界面与主题功能，修改时需要先确认文件位置。

生成并部署网站

确认本地预览正常后依次执行：

三个命令分别完成以下工作：

  1. hexo clean 删除旧缓存和旧的生成结果。
  2. hexo generate 根据 Markdown、配置和主题重新生成 public。
  3. hexo deploy 将生成结果推送到远程 main 分支。

常见问题

部署成功但网页没有更新

先确认生成步骤没有跳过：

再检查 GitHub 仓库的 main 分支是否产生新提交，以及 Pages 发布来源是否为 main 和 / (root)。GitHub Pages 更新可能需要短暂等待，浏览器缓存也可能继续显示旧页面。

不要直接修改 public

public 是 Hexo 自动生成的结果。再次执行 hexo generate 时，直接修改其中 HTML 的内容可能被覆盖。长期维护的内容应写入 source、主题配置或自定义样式文件。
